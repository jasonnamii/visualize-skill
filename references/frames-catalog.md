# 20 Frames Catalog — 논리 카탈로그

각 프레임은 **시각화 기법이 아니라 사고 도구**다. 본질을 압축하는 논리 구조. 프레임별 명세:

- **정의** — 이 프레임이 뭘 주장하는가
- **작동원리** — 어떤 인과·관계를 전제하는가
- **구성요소** — 노드/엣지/축의 의미
- **드러냄** — 이 프레임이 선명하게 만드는 것
- **감춤** — 이 프레임이 지우는 것 (트레이드오프)
- **변별점** — 인접 프레임과의 차이
- **선택 조건** — 언제 이 프레임이 맞는가
- **반례/FAIL** — 언제 이 프레임이 틀리는가

---

## 분류 원리 (3축)

20프레임은 3축으로 분류된다. **MECE 아님 — 중첩 가능**.

| 축 | 값 | 의미 |
|----|----|------|
| 시간성 | 순환 / 선형 / 정지 | 인과가 돌아가는가, 흘러가는가, 멈춰있는가 |
| 관계형식 | 루프 / 계층 / 분포 | 노드가 서로 먹이는가, 쌓이는가, 흩어지는가 |
| 설명대상 | 왜 / 어떻게 / 무엇 | 원리·과정·상태 중 무엇을 설명하는가 |

**프레임 선택 = 본질 질문이 세 축 어디에 놓이는지 확정하는 일.**

---

## GROUP A — 순환·루프 (5개)

**공통 전제:** 시간이 돌아간다. 결과가 다시 원인이 된다. 정적 상태가 아니라 **자기강화 시스템**.

---

### 1. 플라이휠 (Flywheel)

- **정의**: 출력이 다시 입력을 증폭하는 자기강화 루프
- **작동원리**: A→B→C→D→A 단방향 원형 인과. 한 바퀴 돌수록 다음 바퀴 속도↑ (관성·복리)
- **구성요소**:
  - 노드 4~6개 = 원인이자 결과인 상태·행동
  - 엣지 = 단방향 "강화한다"
  - 축 1개 = 원형 회전
- **드러냄**: 왜 시간이 아군인가, 어디가 끊기면 전체가 멈추는가
- **감춤**: 초기 가동 비용(콜드스타트), 외부 충격, 역방향 붕괴 시나리오
- **변별점**:
  - vs 루프 = 플라이휠은 "성장의 가속", 루프는 "반복의 순환"
  - vs Multi-Flywheel = 플라이휠은 1축, Multi는 다축 물림
- **선택 조건**: "왜 커질수록 더 빨라지는가"라는 질문이 핵심일 때
- **반례/FAIL**: 노드가 선형 단계(인지→가입→결제)면 퍼널이 맞음. 플라이휠은 "결제자가 다시 인지를 만든다"가 성립해야 함

---

### 2. 루프 (Loop / Growth Loop)

- **정의**: 입력→처리→출력이 다시 입력을 만드는 자가확산 구조
- **작동원리**: 플라이휠보다 명시적으로 **외부 유입 채널**을 가짐. 사용자 1명이 다음 사용자 N명을 낳음 (K-factor)
- **구성요소**:
  - 노드 4~5개 = 유입·활성화·가치생성·공유·재유입
  - 엣지 = 순환 + 외부 유입 진입점
  - 축 1개
- **드러냄**: 어떤 액션이 다음 유저를 만드는가, 어디가 유실되면 루프가 죽는가
- **감춤**: 유입 품질·리텐션 곡선·경제성
- **변별점**:
  - vs 플라이휠 = 루프는 "유저 확산"에 특화, 플라이휠은 "사업 자산"에 특화
  - vs 퍼널 = 루프는 출구가 다시 입구, 퍼널은 출구가 끝
- **선택 조건**: "자가 확산이 가능한가"·"바이럴이 어떻게 도는가"
- **반례/FAIL**: 외부 유입 없이 닫힌 순환이면 플라이휠. 루프의 본질은 "확산"

---

### 3. Hook Model

- **정의**: 습관 형성 4단계 순환 (Trigger→Action→Reward→Investment)
- **작동원리**: 사용자 뇌에 **조건반사 회로**를 심는 구조. Reward의 **가변성**이 도파민 스파이크를 유발, Investment가 다음 Trigger 민감도를 높임
- **구성요소**:
  - 4 단계 고정 = 이론적 불변
  - 엣지 = 단방향 4→1 회귀
  - 축 1개
  - **가변 보상 강조 표시** (핵심)
- **드러냄**: 왜 돌아오는가, 어디가 약해서 습관화 실패인가
- **감춤**: 초기 획득(acquisition), 윤리적 설계 문제, 다양한 유저 세그먼트
- **변별점**:
  - vs 플라이휠 = Hook은 **개인 내부 루프**(뇌), 플라이휠은 **사업 구조 루프**
  - vs Journey = Hook은 반복 재진입, Journey는 1회 여정
- **선택 조건**: 리텐션 진단, 습관형 제품, "왜 안 돌아오지"
- **반례/FAIL**: 1회성 구매·검색·거래에는 Hook 부적합. 재방문이 가치의 본질이어야 함

---

### 4. Two-sided Market

- **정의**: 공급자와 수요자가 서로를 끌어당기는 양면 플랫폼
- **작동원리**: A가 늘면 B가 늘고, B가 늘면 A가 다시 늘어나는 **교차 네트워크 효과**. 한쪽이 임계점 이하로 떨어지면 양쪽 붕괴
- **구성요소**:
  - 2 그룹(공급·수요) + 1 중앙 플랫폼
  - 엣지 = 양방향 가치 흐름 (가치·수수료·데이터)
  - 축 2개 (양 진영)
- **드러냄**: 닭-달걀 문제, 어느 쪽을 먼저 채워야 하는가, 플랫폼 수수료 구조
- **감춤**: 멀티호밍, 탈중개화 위험, 플랫폼 내부 품질 통제
- **변별점**:
  - vs 플라이휠 = 2면은 2주체, 플라이휠은 1주체 시스템
  - vs Multi-Flywheel = 2면은 "양쪽 균형", Multi는 "여러 루프 물림"
- **선택 조건**: 마켓플레이스·중개 플랫폼·양쪽 모두가 고객인 구조
- **반례/FAIL**: 한쪽이 원료공급에 가까운 B2B 공급체인은 Two-sided 아님 (가치사슬)

---

### 5. Multi-Flywheel

- **정의**: 2~4개 플라이휠이 서로를 구동하는 복합 루프 시스템
- **작동원리**: 각 휠 = 독립된 자기강화 구조, 휠 사이 **연결점**에서 한 휠의 출력이 다른 휠의 입력이 됨. 시스템 전체의 관성·복리
- **구성요소**:
  - 2~4 휠 × 각 4~6 노드 = 전체 12~20 노드
  - 엣지 = 각 휠 내부 순환 + 휠 간 연결
  - 축 다수
- **드러냄**: 왜 경쟁자가 한 축만 따라오면 못 이기는가, 플랫폼의 시스템적 해자
- **감춤**: 각 휠의 세부, 우선순위, 실행 순서
- **변별점**:
  - vs 플라이휠 = 단일 vs 복합 (복잡도 N배)
  - vs 생태계맵 = Multi-Flywheel은 휠 간 **인과 연결 명시**, 생태계맵은 단순 관계망
- **선택 조건**: 복합 플랫폼·다사업부 기업·시스템적 경쟁우위 설명
- **반례/FAIL**: 2개 사업이 서로 구동하지 않는 단순 병렬 구조면 Multi-Flywheel 아님 (그냥 사업 포트폴리오)

---

## GROUP B — 선형·흐름 (4개)

**공통 전제:** 시간이 한 방향으로 흐른다. 출발점과 도착점이 있다. **상태 변화**를 보여준다.

---

### 6. 퍼널 (Funnel)

- **정의**: 단계별 전환·누수를 수직으로 시각화
- **작동원리**: 상단 모집단이 각 단계에서 일정 비율만 다음으로 넘어감. 각 단계는 **되돌아오지 않음** (일방통행)
- **구성요소**:
  - 4~6 단계 (8 초과 금지)
  - 단계별 너비 = 잔존 비율
  - 엣지 = 단계간 전환율 라벨
  - 축 1개 (수직)
- **드러냄**: 어디서 새는가(병목), 전환율 수준, 개선 우선순위
- **감춤**: 이탈자의 이유, 시간 경과, 반복 구매, 재진입
- **변별점**:
  - vs 루프 = 퍼널은 출구가 끝, 루프는 출구가 다시 입구
  - vs Journey = 퍼널은 전환율, Journey는 감정·경험
- **선택 조건**: 마케팅·세일즈 전환 진단, 단일 여정의 누수 분석
- **반례/FAIL**: 재구매·구독·리텐션이 본질이면 퍼널이 왜곡. 재진입 모델(루프·Hook) 우선

---

### 7. 브리지 (Bridge / Transformation)

- **정의**: 현재 상태(AS-IS)에서 목표 상태(TO-BE)로 건너가는 전환 장치
- **작동원리**: 좌·우 두 상태가 **질적으로 다르다**는 가정. 중앙의 전환 장치(솔루션·개입)가 그 격차를 건너게 함
- **구성요소**:
  - 3 영역 = AS-IS · 전환 · TO-BE
  - 엣지 = 좌→우 단방향
  - 축 1개 (수평)
- **드러냄**: 문제·해결·결과의 구조, 서비스가 무엇을 바꾸는가
- **감춤**: 시간·비용·실행 난이도, 중간 단계의 세부
- **변별점**:
  - vs 퍼널 = 브리지는 "전후 상태", 퍼널은 "단계별 누수"
  - vs Unbundling = 브리지는 개인·조직 변화, Unbundling은 산업 재편
- **선택 조건**: 컨설팅 제안·서비스 정의·변화관리 (문제→솔루션→효과)
- **반례/FAIL**: 연속 스펙트럼(정도의 차이)이면 브리지 부적합. 질적 상태 변화가 있어야 함

---

### 8. Experience Journey Map

- **정의**: 시간축 위의 사용자 경험 단계와 감정 곡선
- **작동원리**: 사용자는 제품과 **일련의 접점**을 거치며 각 접점에서 **감정 상태**가 변함. 감정 곡선의 저점 = 이탈 위험
- **구성요소**:
  - 시간축(수평)
  - 단계 노드 5~9개
  - 감정 곡선(수직, +/-)
  - 이탈 포인트 강조
- **드러냄**: 고객 경험의 질적 변화, 어디서 실망하는가, 개선 기회 포인트
- **감춤**: 정량 전환율, 반복 사용, 세그먼트 차이
- **변별점**:
  - vs 퍼널 = Journey는 **질·감정**, 퍼널은 **양·전환율**
  - vs Hook = Journey는 1회 완결, Hook은 재진입 루프
- **선택 조건**: UX 개선·서비스 설계·고객 이해
- **반례/FAIL**: 감정·질 정보가 없고 수치만 있으면 퍼널이 정직. Journey는 정성 데이터가 있어야 함

---

### 9. 가치사슬 (Value Chain)

- **정의**: 원료에서 최종 소비까지 가치가 생성·이전되는 단계
- **작동원리**: 각 단계는 **부가가치를 더함**. 단계별 마진·병목·지배력이 서로 다름. 전체 체인의 수익성 = 각 단계 마진의 합
- **구성요소**:
  - 5~7 단계 (공급·생산·유통·판매·소비)
  - 엣지 = 가치·상품·돈의 흐름
  - 단계별 마진·병목 표시
  - 축 1개 (수평)
- **드러냄**: 산업의 돈 흐름, 어디서 마진이 나는가, 병목 지점
- **감춤**: 플랫폼·네트워크 구조, 수요자 행동
- **변별점**:
  - vs 퍼널 = 가치사슬은 **산업 구조**, 퍼널은 **단일 기업의 고객 전환**
  - vs Control Point = 가치사슬은 전체 흐름, Control Point는 지배 노드만
  - vs Unbundling = 가치사슬은 현재 구조, Unbundling은 재편 결과
- **선택 조건**: 산업 분석·경쟁 포지셔닝·진입 전략
- **반례/FAIL**: 플랫폼·양면시장은 사슬 아님. Two-sided·Multi-Flywheel이 맞음

---

## GROUP C — 계층·구조 (5개)

**공통 전제:** 정지된 구조다. 시간이 흐르지 않고 **쌓여있다**. 상하·포함·의존 관계를 보여준다.

---

### 10. 레이어/스택 (Layer Stack)

- **정의**: 층층이 쌓인 의존 구조
- **작동원리**: 상위층은 하위층에 의존. 하위층 교체 시 상위층 붕괴. 층 간 **경계와 인터페이스**가 본질
- **구성요소**:
  - 3~5 층 (수평 막대)
  - 엣지 = 상하 의존 (암묵)
  - 축 1개 (수직)
- **드러냄**: 사업·기술·조직의 층 구조, 어느 층에서 경쟁하는가
- **감춤**: 동적 상호작용, 시간 변화, 수평 확장
- **변별점**:
  - vs 피라미드 = 레이어는 **의존**(하위가 상위 지탱), 피라미드는 **면적**(하위가 더 많음)
  - vs Capability Stack = Layer는 일반 구조, Capability는 경쟁우위 특화
- **선택 조건**: 플랫폼·기술스택·조직 설명
- **반례/FAIL**: 층 간 의존이 불명확하면 레이어 부적합. 매트릭스·네트워크가 맞음

---

### 11. 피라미드 (Pyramid)

- **정의**: 하위 기반이 상위 성과를 받치는 삼각 구조
- **작동원리**: 하위층은 **더 넓은 기반**(인원·예산·시간). 상위로 갈수록 **희소·핵심**. 하위 부실 시 상위 붕괴
- **구성요소**:
  - 3~5 단계 (삼각형)
  - 하위 면적 > 상위 면적
  - 축 1개 (수직)
- **드러냄**: 기반의 중요성, 상위 성과의 희소성, 우선순위
- **감춤**: 수평 관계, 동적 변화
- **변별점**:
  - vs 레이어 = 피라미드는 **면적 차이**(양적 기반), 레이어는 **동등 막대**(논리적 의존)
  - vs 매트릭스 = 피라미드는 1축, 매트릭스는 2축
- **선택 조건**: 성숙도 모델·인재 피라미드·매슬로우형 우선순위
- **반례/FAIL**: 각 층이 동등한 중요성이면 레이어. 피라미드는 "기반이 더 크다"가 전제

---

### 12. Capability Stack

- **정의**: 경쟁우위를 만드는 핵심 능력들의 누적 구조
- **작동원리**: 각 능력은 **개별적으로는 흉내낼 수 있음**. 조합·누적 시 모방 불가능(해자). 상위 능력은 하위 능력의 조합 결과
- **구성요소**:
  - 3~5 능력층
  - 조합 효과 강조 (곱·시너지)
  - 축 1개 (수직)
- **드러냄**: 왜 우리가 이기는가, 경쟁자가 못 따라오는 이유
- **감춤**: 시장 변화·고객·외부 위협
- **변별점**:
  - vs 레이어 = Capability는 **경쟁우위 특화**, 레이어는 일반 구조
  - vs Control Point = Capability는 내부 역량, Control Point는 외부 위치
- **선택 조건**: 경쟁우위 정의·M&A 대상 평가·투자 설득
- **반례/FAIL**: 한 가지 역량만 있으면 Stack 아님. 3개 이상 + 조합 효과가 있어야 함

---

### 13. JTBD 맵 (Jobs-to-be-Done)

- **정의**: 고객이 "고용한" 일(Job) 중심의 동기 구조
- **작동원리**: 고객은 제품이 아니라 **해결하고 싶은 일**을 산다. Job = 상황(Situation)에서 동기(Motivation)로 원하는 결과(Outcome)에 도달, 장애물(Obstacle)이 막음
- **구성요소**:
  - 핵심 노드 5개 (Job·Situation·Motivation·Outcome·Obstacle)
  - 엣지 = 논리 연결 (암묵)
  - 축 구조적 (정지)
- **드러냄**: 고객의 진짜 동기, 숨은 경쟁자(기능이 아닌 Job 차원), PMF 방향
- **감춤**: 실행·유통·가격, 사업 구조
- **변별점**:
  - vs Journey = JTBD는 **동기 구조**(정지), Journey는 **경험 흐름**(시간)
  - vs Unit Economics = JTBD는 **왜 사는가**, UE는 **얼마 버는가**
- **선택 조건**: PMF 이전·신규사업·본질 정의
- **반례/FAIL**: Job이 불명확하거나 "제품이 곧 Job"이면 JTBD 부적합. 기능 중심 로드맵이 맞음

---

### 14. Strategic Control Point

- **정의**: 가치사슬 전체를 지배하는 결정적 지점
- **작동원리**: 사슬의 특정 노드가 **병목·독점·표준**이 되어 전·후 단계를 좌우. 그 지점을 잡으면 나머지 사슬의 가치가 흡수됨
- **구성요소**:
  - 가치사슬(5~7 단계)
  - 지배 노드 1~2개 강조
  - 영향 화살표 (지배점→타 단계)
- **드러냄**: 어디를 잡아야 산업을 먹는가, 플랫폼·독점 전략
- **감춤**: 경쟁 구도의 변화, 우회 가능성
- **변별점**:
  - vs 가치사슬 = Control Point는 **지배점 특화**, 가치사슬은 전체 흐름
  - vs Capability Stack = Control Point는 **외부 위치**, Capability는 내부 역량
- **선택 조건**: 플랫폼 전략·독점 설계·M&A 타깃 식별
- **반례/FAIL**: 모든 단계가 평등하면 Control Point 없음. 가치사슬로 끝남

---

## GROUP D — 분포·매핑 (4개)

**공통 전제:** 2차원 공간에 항목을 **배치**한다. 상대적 위치로 의미 생성. 시간·인과 없음.

---

### 15. 매트릭스 (Matrix)

- **정의**: 2축 분류로 4사분면을 만드는 의사결정 프레임
- **작동원리**: 2개의 **직교하는 기준**(축)으로 공간 분할. 각 사분면은 **다른 행동 전략**을 요구 (예: 긴급×중요 → Do·Schedule·Delegate·Drop)
- **구성요소**:
  - 2축 (수평·수직)
  - 4사분면
  - 항목 점·라벨
  - 사분면별 전략 이름 (선택)
- **드러냄**: 분류 기준, 우선순위, 의사결정 룰
- **감춤**: 연속 스펙트럼·시간 변화·3번째 이상 차원
- **변별점**:
  - vs 포지셔닝 맵 = 매트릭스는 **의사결정 프레임**(사분면 전략), 포지셔닝은 **시장 지도**(경쟁 배치)
  - vs 피라미드 = 매트릭스는 2축, 피라미드는 1축
- **선택 조건**: 의사결정·우선순위화·분류
- **반례/FAIL**: 축이 독립적이지 않거나(상관관계) 항목이 연속 분포면 매트릭스 부적합

---

### 16. 포지셔닝 맵 (Positioning Map)

- **정의**: 시장 내 경쟁 위치를 2축으로 그린 지도
- **작동원리**: **시장 소비자 인식**의 2대 기준(예: 품질·가격)으로 경쟁사·자사 위치 배치. 빈 공간 = 기회, 밀집 공간 = 레드오션
- **구성요소**:
  - 2축 (브랜드 인식 기준)
  - 경쟁사 점
  - 자사 강조 (차별화 방향)
- **드러냄**: 경쟁 구도, 차별화 방향, 빈 틈
- **감춤**: 시장 규모·성장률·수익성, 소비자 세그먼트
- **변별점**:
  - vs 매트릭스 = 포지셔닝은 **경쟁 지도**, 매트릭스는 **의사결정 도구**
  - vs JTBD = 포지셔닝은 공급자 중심(기능·가격), JTBD는 수요자 중심(동기)
- **선택 조건**: 브랜드 전략·시장 진입·차별화 설계
- **반례/FAIL**: 소비자가 인식하지 못하는 기준(내부 지표)으로 축 설정 시 무의미. **소비자 인식 축**이 필수

---

### 17. North Star Metric 트리

- **정의**: 최상위 지표를 하위 드라이버로 분해한 트리
- **작동원리**: NSM = 사업 가치의 최고 대리지표. 수학적·인과적으로 하위 지표의 **곱·합**으로 분해 가능 (예: Revenue = Users × Frequency × ARPU)
- **구성요소**:
  - 1 NSM (루트)
  - 3~5 1차 드라이버
  - 9~15 2차 input metric
  - 엣지 = 수학/인과 분해
  - 축 구조 (트리)
- **드러냄**: 무엇을 올려야 사업이 자라는가, 팀별 목표 정렬
- **감춤**: 정성적 가치·장기 리스크·지표 간 트레이드오프
- **변별점**:
  - vs Unit Economics = NSM은 **성장 지표 분해**, UE는 **수익성 지표 분해**
  - vs 피라미드 = NSM은 수학 분해, 피라미드는 면적 위계
- **선택 조건**: OKR·성장팀·지표 정렬
- **반례/FAIL**: 최상위 지표가 사업 본질을 왜곡(예: DAU만 올리다 수익 붕괴)하면 NSM 자체를 재정의해야 함

---

### 18. Unit Economics 트리

- **정의**: 사용자·거래 단위 경제성(LTV·CAC·Margin)을 분해한 트리
- **작동원리**: **한 명(한 건)** 기준 수익·비용 분해. LTV/CAC ≥ 3이 생존선. 각 노드는 수식으로 상위 노드에 기여
- **구성요소**:
  - 루트 = LTV/CAC 또는 Payback
  - 가지 = LTV 분해 (ARPU×기간×마진) / CAC 분해 (획득비용·채널별)
  - 엣지 = 수식 분해
  - 축 = 트리
- **드러냄**: 사업이 돈이 되는가, 어디가 새는가, 확장 여력
- **감춤**: 시장 크기·정성 가치·장기 전략
- **변별점**:
  - vs NSM = UE는 수익성, NSM은 성장성
  - vs 가치사슬 = UE는 **자사 단위 경제**, 가치사슬은 산업 전체 흐름
- **선택 조건**: VC 투자 검증·확장 판단·가격 설계
- **반례/FAIL**: 단위가 불명확한 사업(초기·실험 단계)은 UE 강요하면 왜곡. PMF 이후에 맞음

---

## GROUP E — 관계망·재편 (2개)

**공통 전제:** 다수 주체의 **관계 구조** 또는 그 **변형**.

---

### 19. 생태계 맵 (Ecosystem Map)

- **정의**: 산업 내 주체들(사용자·파트너·공급자·기관·경쟁자)의 관계망
- **작동원리**: 노드 = 주체, 엣지 = 영향·거래·경쟁 관계. 중앙 주체(플랫폼) 있을 수도, 다중심일 수도. **네트워크 위상**이 본질
- **구성요소**:
  - 5~15 노드 (주체 유형별 색)
  - 엣지 = 관계 유형 (영향·돈·정보)
  - 축 없음 (공간 배치)
- **드러냄**: 산업판, 누가 누구를 움직이는가, 빈 자리(미결합)
- **감춤**: 시간 변화, 수익성, 거래량
- **변별점**:
  - vs Multi-Flywheel = 생태계는 **관계만**, Multi는 **인과 연결 명시**
  - vs 가치사슬 = 생태계는 **망**, 가치사슬은 **선형**
- **선택 조건**: 산업 분석·파트너십 설계·시장 진입 지도
- **반례/FAIL**: 노드 15개+이면 한 장 부적합. 핵심 5~9개로 축약하거나 다층 분할

---

### 20. Unbundling/Rebundling 맵

- **정의**: 기존 가치사슬의 해체와 재조립 구조
- **작동원리**: 번들된 서비스(은행·신문·대학)를 **구성요소로 분해** → 각 요소를 **특화 업체**가 제공 → 새로운 방식으로 **재조립**. 파괴적 혁신의 핵심 메커니즘
- **구성요소**:
  - 3 영역 = AS-IS 사슬 · 분해 · 재조립
  - AS-IS: 기존 번들 단일 주체
  - 분해: 특화 업체들
  - 재조립: 새로운 번들/언번들 구조
- **드러냄**: 기존 산업이 왜 깨지는가, 새로운 승자 구도
- **감춤**: 실행 난이도·규제·기존 플레이어 대응
- **변별점**:
  - vs 가치사슬 = 가치사슬은 현재, Unbundling은 **변형 과정**
  - vs 브리지 = Unbundling은 **산업 재편**, 브리지는 **개인·조직 변화**
- **선택 조건**: 파괴적 혁신·시장 재정의·신규 진입 설계
- **반례/FAIL**: 기존 산업이 이미 해체된 상태면 Unbundling 의미 없음. 번들 구조가 전제

---

## 7대 본질 질문 → 프레임 라우팅

| 질문 | 1순위 | 2순위 | 논리 |
|------|-------|-------|------|
| 왜 존재하는가 | JTBD | - | 고객 동기 구조가 곧 존재 이유 |
| 왜 성장하는가 | Flywheel | Loop·NSM·Multi-Flywheel | 자기강화 구조 또는 지표 분해 |
| 왜 계속 쓰는가 | Hook | Journey | 습관화 루프 또는 경험 여정 |
| 왜 돈이 되는가 | Unit Economics | Capability Stack | 단위 경제 또는 경쟁우위 |
| 왜 우리가 이기는가 | Capability Stack | Control Point | 내부 역량 또는 외부 위치 |
| 어디서 깨지는가 | Funnel | Journey | 정량 누수 또는 정성 이탈 |
| 시장이 어떻게 바뀌는가 | Value Chain | Unbundling | 현재 흐름 또는 재편 구조 |

## 프레임 선택 결정 트리

```
1. 시간이 흐르는가?
   아니오 → 정지 구조 → Group C(계층) or Group D(분포)
     · 상하 의존? → Group C
     · 2축 배치? → Group D
   예 → 2.

2. 되돌아오는가 (순환)?
   예 → Group A (플라이휠·루프·Hook·Two-sided·Multi)
     · 1주체 자기강화? → Flywheel/Loop
     · 2주체 양면? → Two-sided
     · 여러 루프 물림? → Multi-Flywheel
     · 개인 습관 루프? → Hook
   아니오 → 3.

3. 단방향 흐름인가?
   예 → Group B (퍼널·브리지·Journey·가치사슬)
     · 전환율 수치? → Funnel
     · 감정·경험? → Journey
     · 전후 상태? → Bridge
     · 산업 돈 흐름? → Value Chain

4. 관계망인가?
   예 → Group E (생태계맵·Unbundling)
     · 현재 구조? → Ecosystem Map
     · 재편 과정? → Unbundling
```

## 프레임 결합 패턴 (중급)

단일 프레임으로 부족할 때 2개 결합:

| 결합 | 용도 |
|------|------|
| Flywheel + Unit Economics | "왜 커지며 왜 돈이 되는가" — 성장·수익 동시 설명 |
| Two-sided + Control Point | 플랫폼 설계 — 양면 구조 + 지배점 |
| JTBD + Journey | 고객 이해 — 동기 구조 + 경험 흐름 |
| Funnel + Hook | 획득→리텐션 전체 — 선형 유입 + 순환 유지 |
| Value Chain + Unbundling | 산업 진단·재편 전략 |
| Capability Stack + Multi-Flywheel | 해자의 시스템적 복리 |

**결합 시:** 본질 질문이 **두 축**이면 결합, **한 축**이면 단일 프레임 유지.
